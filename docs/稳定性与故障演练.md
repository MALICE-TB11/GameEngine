# 稳定性与故障演练（M4 之后的修整）

M4 完成后对引擎做了一轮外部审查（审查对象是 M4 提交前的工作区），逐条对照代码核实后修了下面这些问题。
这篇笔记记录**每个问题为什么是问题、怎么修的、用什么测试或演练证明修好了**，以及暂时不做、留到后面的事项。

## 一条统一的规则
> 可恢复的失败：**报错、保留旧的（或用默认的）、继续运行**；绝不覆盖用户数据、绝不让异常把进程带走。

| 对象 | 失败时 |
|---|---|
| shader | 保留旧管线，错误显示在 Shader 面板（M2 起） |
| 模型 / 贴图 | 兜底模型（品红棋盘）或默认贴图；热重载失败保留旧版本 |
| 场景文件 | 不覆盖原文件，临时用演示场景，保存写到 `recovered_<原名>` |
| `.meta` | 字段类型错 → 该字段用默认值并警告；整个文件写坏 → 沿用上次的设置 |
| 配置数值 | 夹到合法范围并警告（`clampSetting` / `App::sanitizeSettings`） |
| 后台任务抛异常 | 任务边界捕获、记错误日志；资产任务转成「加载失败」并照常收尾 |
| pass 被关 / 没准备好 | 下游读默认资源；被外部直接采样的贴图真的清成默认值 |

## 修了什么

### 1. 场景文件写坏会被演示场景覆盖（数据丢失）
以前 `openScene()` 失败一律当作「文件不存在」，生成演示场景并**保存到原路径**。少一个括号，整个场景就没了。
现在区分「不存在」与「读不出来」：后者报错、原文件不动，当前场景路径改成 `recovered_<原名>`，之后 Ctrl+S 也写不回坏文件。
**演练**：截掉场景文件末尾 20 个字符后用 `--scene` 启动 → 返回码 2（有错误日志），文件哈希不变。

### 2. 材质检视器的悬空指针
编辑器长期保存 `Material*`。模型热重载会整个换掉材质数组（旧的延迟销毁），检视器继续解引用旧指针就是访问已释放内存。
现在保存「模型句柄 + 材质下标 + 模型版本」，每帧通过 `Editor::selectedMaterial()` 重新解析；版本对不上（被热重载过）就自动取消选择。
这和 M3.5 的约定是同一个道理：**跨帧只存句柄，指针只在本帧内用**。

### 3. 后台任务的异常会终止进程
`.meta` 里 `"maxLods": "4"` 这样的类型错误会让 `json::value()` 抛异常；Job 线程入口没有捕获，异常逃出线程函数 → `std::terminate`。
- `JobSystem` 的每个执行点（工作线程、`wait` 时帮忙执行、同步回退、主线程队列）都经过 `runGuarded`：捕获、记日志、计数照常减一。
- `AssetManager` 的加载任务在自己内部把异常转成「加载失败」，**保证回到主线程收尾**（否则槽位永远「加载中」、`pendingCount` 永不归零，冒烟测试会等到超时）。
- `.meta` 的每个字段单独做类型保护，读错的字段用默认值。

### 4. 同步：上传与读后读
**缓冲上传**：以前只靠 fence 等待。fence 只说明「执行完了」，不说明「后续读取能看到写入」。现在拷贝后加一个
`TRANSFER_WRITE → ALL_COMMANDS / MEMORY_READ` 的内存屏障 —— pipeline barrier 的第二个同步范围包含同一队列上提交顺序更晚的命令，所以放在上传命令里就覆盖了之后所有帧。
贴图上传的目标阶段补上了 compute（M5 的 FFT 会在 compute 里采样）。

**Render Graph 的读后读**：以前「同布局的读之后再读」只合并阶段、不插 barrier。问题是之前那个 barrier 的目标阶段只覆盖了第一个读者：

```
compute 写 ──barrier(→ 顶点/片元)──▶ 图形 pass 采样 ──(无 barrier)──▶ compute 采样   ← 与写入没有依赖！
```

现在新读者的阶段如果没被覆盖（`target.stage & ~cur.stage ≠ 0`），补一个「最近一次写入 → 新阶段」的 barrier（布局不变）。同阶段的第二个读者仍然不需要 barrier。
原来有个单元测试恰好断言了「这里不需要 barrier」—— 那条断言本身是错的，已改正。

### 5. 编辑器视口绕过了默认贴图替换
视口贴图由 ImGui 用**提前缓存的描述符**直接采样。写它的 pass（Tonemap / FXAA）被关掉时，图内部会给读者换成默认贴图的 view，但 ImGui 看到的仍是真实图像：旧画面，或刚缩放后未初始化、布局不对的显存。
新增 `TextureDesc::externalRead`：这类贴图在「被读但本帧没人写」时，图会先把真实图像**清成默认值**再转成采样布局。
**A/B 验证**：关掉这个标记、`--disable-pass FXAA` 在编辑器模式下运行 → validation 报布局错误（返回码 2）；打开 → 干净。

### 6. 地形：三个表面统一成一个
同一组采样，以前有三种表面：渲染网格沿 (x+1,z)–(x,z+1) 对角线切格子、Jolt 沿 (x,z)–(x+1,z+1) 切、`heightAt()` 用双线性插值。四个角不共面时三者相差可达几十厘米 —— 脚底悬空或陷地、M6 的水深判断不一致。
现在三者都用 Jolt 的切法：

$$h(t_x,t_z)=\begin{cases}h_{00}+t_x(h_{10}-h_{00})+t_z(h_{11}-h_{10}) & t_x\ge t_z\\ h_{00}+t_z(h_{01}-h_{00})+t_x(h_{11}-h_{01}) & t_x<t_z\end{cases}$$

**测试**：在起伏剧烈的地形上取 400 个格内点，`heightAt()` 与 Jolt 射线命中高度之差 < 2 cm（Jolt 按块把高度量化为 8 位，约 1 cm）。
这个测试顺带抓到一个真 bug：平台半径为 0 时 `smoothstep(0, 0, r)` 在原点算出 0/0 = NaN，写进高度场后成了碰撞体上的窟窿。

### 7. 其他
- `.meta` 改动触发热重载时，以前读的是登记时缓存的设置；现在烘焙前重新读 `.meta`。
- 初始化失败（例如交换链创建失败）后的清理：所有渲染模块的 `shutdown()` 在没初始化时直接返回。
- 配置数值范围：`FixedStepLoop` 自己保证 `maxFrameTime ≥ fixedDt`（以前负值会让 `std::clamp` 未定义）；其余在 `App::sanitizeSettings` 统一检查（阴影图集取 2 的幂、地形分辨率取最近的 32×2ⁿ+1……）。
- 冒烟测试在 `shutdown()` **之后**统计错误日志：销毁阶段的 validation 报错也会让它失败。
- 冒烟测试结束时打印帧时间 平均 / P50 / P95 / P99 / 最长，以及因补步上限丢弃的模拟时间。

## 故障演练清单（里程碑验收的一部分）
| 演练 | 怎么做 | 期望 |
|---|---|---|
| 关掉 pass 后缩放窗口 | `sandbox --frames 45 --validation --disable-pass FXAA`（以及 `Tonemap`、`Tonemap,FXAA`、`Terrain,Forward,Sky`），编辑器模式；冒烟测试中途会缩放窗口 | 返回码 0 |
| 场景文件损坏 | 截断一个场景文件，`--scene` 打开 | 返回码 2，原文件不变 |
| `.meta` 类型错误 / JSON 损坏 | 单元测试「资产：.meta 里类型写错……」 | 烘焙成功，不抛异常 |
| 后台任务抛异常 | 单元测试「Job 系统：任务抛异常……」 | 进程不退出，计数归零 |
| 渲染图读后读 | 单元测试「Render Graph：先被图形 pass 采样……」 | compute 读者有 barrier |
| 地形表面一致 | 单元测试「地形：CPU 高度查询与 Jolt 碰撞体是同一个表面」 | 误差 < 2 cm |
| 选中材质时热重载 | 资源 → 材质里选中遗迹的材质，然后修改 `ruins.glb`（例如重新运行 `make_test_assets.py`） | 检视器自动退回，不崩溃 |
| shader 编译失败后恢复 | 在 `terrain.hlsl` 里写一个语法错误并保存，再改回来 | 地形保持旧画面 + 错误提示，改回后恢复 |

## 暂不处理（已记录，按需要排进后续里程碑）
| 事项 | 为什么现在不做 | 计划 |
|---|---|---|
| shader 后台编译 | 目前一次热重载编译 1–2 个 shader，卡顿可接受；后台编译要处理「编译期间又改了一次」 | M6.5 前（体积云 shader 编译慢） |
| 按字节/耗时预算安排 GPU 上传 | 现有资产小；`AssetManager::update` 每帧 4 个任务 | 接入大模型或流式加载时 |
| 显存预算与资源回收（引用计数、卸载未用模型） | 当前场景约 200 MB，远低于 2 GB | M5 海洋（FFT 贴图）后统计峰值再做 |
| 外部 `.gltf` 引用的 `.bin` / 贴图进入依赖追踪 | 目前资产都是 `.glb`（单文件） | 第一次导入 `.gltf` 资产时 |
| shader 描述符绑定 / push constant 与 C++ 布局的兼容性检查 | 需要 SPIR-V 反射（SPIRV-Reflect） | 和「轻量反射」一起做 |
