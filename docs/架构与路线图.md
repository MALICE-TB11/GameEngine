# 架构与路线图

本文是 M3 之后所有工作的依据：引擎分几层、每层要建什么；海洋与大气天气系统怎么做；按什么顺序做。
每个里程碑开工前先对照这里，完成后更新「状态」列。

## 1. 五层架构

与 GAMES104 / Piccolo 的五层模型一致。只能从上往下依赖，同层模块之间通过 `world`、`medium` 的接口交流。

```
工具层   editor/（编辑器） tools/（导入烘焙命令行） sandbox/              —— 只在开发期存在
功能层   world physics terrain ocean atmosphere medium animation audio ai gameplay render
资源层   asset/（资产数据库、句柄、导入器、烘焙器、异步加载、热重载）    —— 待建（M3.5）
核心层   core/（日志 配置 Job系统 帧内存 序列化 轻量反射）             —— 部分完成
平台层   platform/（窗口 输入 虚拟文件系统） rhi/（Vulkan）
```

| 层 | 现状 | 要补的 | 为什么 |
|---|---|---|---|
| 平台层 | 窗口、输入轮询、Vulkan 设备/交换链 | 动作映射与手柄；虚拟路径 `assets://`、`config://`；3D 贴图、立方体贴图支持 | 魂类必须支持手柄；虚拟路径是打包发布的前提；体积云噪声和环境探针需要 3D / Cube 贴图 |
| 核心层 | 日志、断言、配置、文件监视、固定步长 | Job 系统（先线程池）；帧线性分配器；**轻量反射**（一个宏同时生成 ImGui 检视界面和 JSON 读写） | 异步加载、物理、FFT 的 CPU 回读都需要并行；反射让「加一个参数」不再需要手写界面 |
| 资源层 | glTF/PNG 直接加载 | `AssetHandle<T>`（ID+版本号）；GUID 与 `.meta`；导入 → 烘焙 → 异步加载；KTX2/BC 压缩；缺失资产用错误网格/贴图兜底 | 热重载后引用不悬空；改名不断引用；2GB 显存下贴图必须压缩 |
| 功能层 | world（大结构体实体）、render | 组件化实体；渲染提取（world → 渲染数据）；海洋、大气、地形、物理、动画、战斗、AI、音效 | 渲染与玩法解耦，便于多线程；魂类核心玩法 |
| 工具层 | 停靠式编辑器 | 场景保存/加载；撤销/重做；ImGuizmo 操纵杆；编辑器内运行（复制 world）；Tracy 性能分析；资源缩略图与拖放导入 | 场景写死在代码里是当前编辑器最大的缺口 |

### 资产导入
- **已支持** glTF 2.0（.gltf/.glb）：Blender 直接导出，Fab / Sketchfab / Poly Haven 资产大多提供 glTF。
- **FBX / OBJ**：不进引擎运行时，由离线导入工具（或 Blender）转为 glTF —— FBX 官方 SDK 闭源。
- **贴图**：导入时压缩为 KTX2（颜色 BC7、法线 BC5、单通道 BC4），显存省 4–8 倍；生成完整 mip。
- **网格**：导入时用 meshoptimizer 优化顶点缓存并生成 LOD 链。
- **流程**：源资产 `assets/source/` → 导入器 → 烘焙产物 `assets/cooked/` + `.meta`（GUID、导入设置）→ Job 系统异步加载。
- **免费写实资产**：Poly Haven、ambientCG（CC0）；Quixel/Fab、Sketchfab 需逐个确认授权。

## 2. 海洋系统

目标效果：开阔海面随机、自然；风速/风向/波高/波长密度可调；浪尖翻腾生成泡沫并随波漂移、逐渐消散；阳光碎闪；天空与云的反射；近岸与物体交互。

### 2.1 为什么不用「噪波形变」
Perlin 噪声位移的海面有两个根本问题：**没有色散**（真实海浪波长越长传播越快，$\omega^2 = gk$），**没有统计规律**（波高、周期与风速无关）。看起来总像在「蠕动」而不是「传播」。

我们分两层，两层都来自流体方程：

| 尺度 | 方法 | 物理来源 |
|---|---|---|
| 开阔海面（米到公里） | **频谱 FFT 海洋**（Tessendorf） | 线性水波理论：势流 + 自由表面边界条件 → 每个波矢 $\mathbf{k}$ 独立传播，满足色散关系 |
| 局部交互（近岸、物体、角色，几十米） | **波动方程**（参考实现）→ **浅水方程 SWE**（优化实现） | 浅水近似下的 Navier–Stokes 积分形式 |

> 说明：完整三维 Navier–Stokes（FLIP/SPH）模拟开阔海洋在实时下不可行；「卷浪」这类翻卷结构也无法用高度场表达，用泡沫 + 飞沫粒子近似。

### 2.2 FFT 频谱海洋
1. **初始频谱**（只在参数改变时计算）：
   - 色散关系（有限水深）：$\omega(k) = \sqrt{gk\tanh(kh)}$
   - 频谱：**JONSWAP**（风区有限的风浪）× **TMA** 浅水修正（水深 $h$ 影响），可叠加一个**涌浪**（swell）分量；方向分布用 $\cos^{2s}$ 或 Donelan-Banner。
   - 随机性：$\tilde h_0(\mathbf k) = \frac{1}{\sqrt 2}(\xi_r + i\xi_i)\sqrt{S(\mathbf k)\Delta k_x\Delta k_y}$，$\xi$ 为高斯随机数 —— 这就是「海浪随机」的来源，种子可调。
2. **每帧演化**（compute）：$\tilde h(\mathbf k,t) = \tilde h_0(\mathbf k)e^{i\omega t} + \tilde h_0^*(-\mathbf k)e^{-i\omega t}$，同时生成水平位移 $\tilde{\mathbf D} = -i\frac{\mathbf k}{|\mathbf k|}\tilde h$ 与斜率。
3. **IFFT**（compute，Stockham 蝶形，256² 或 512²）→ 位移贴图（xyz）+ 法线/斜率贴图。
4. **多级联**：3–4 个尺度（例如 250 m / 50 m / 10 m / 2 m），各自负责一段波长，叠加后既有大浪又有细碎波纹，远处不出现重复平铺。
5. **可调参数**（config + ImGui）：风速 $U_{10}$、风向、风区长度（fetch）、水深、浪尖尖锐度 λ（choppiness）、各级联的波长范围与强度、随机种子、时间缩放。**波高**由风速与 fetch 决定（JONSWAP 统计关系），**密度**由峰值频率与级联波长范围决定。

### 2.3 泡沫（浪尖翻腾）
- **来源 1：浪尖折叠**。水平位移的雅可比行列式 $J = (1+\lambda D_{x,x})(1+\lambda D_{y,y}) - \lambda^2 D_{x,y}^2$；$J$ 越小表示表面被挤压、接近破碎。$J < J_{\text{阈值}}$ 处注入泡沫。
- **累积与消散**：泡沫存在一张**持久贴图**里，每帧 $F_{t+1} = F_t\cdot e^{-\Delta t/\tau} + \text{注入}$，并按海面水平速度做半拉格朗日平流 —— 泡沫会拖出条纹、随浪漂走、慢慢消失，而不是逐帧闪烁。
- **来源 2：浅水破碎**。SWE 中波高/水深比超过约 0.78（破碎判据）或速度散度过大处注入泡沫；近岸按水深衰减。
- **外观**：泡沫覆盖率 × 细节泡沫贴图；泡沫区域粗糙度变大、反照率变高、法线变平；可选飞沫粒子。
- **天气联动**：风速越大，阈值越宽松、注入越多（风暴海面大片白浪）。

### 2.4 局部交互：波动方程 → 浅水方程
- **参考实现（波动方程）**：$\partial_t^2 u = c^2\nabla^2 u$，三层显式格式
  $u^{n+1} = u^n + \gamma(u^n - u^{n-1}) + c^2\Delta t^2 \nabla_h^2 u^n$（$\gamma$ 为能量保留系数），5 点拉普拉斯；稳定条件 $c\Delta t/\Delta x < 1/\sqrt2$（**代码中强制钳制**）；障碍处反射边界；网格边缘海绵层吸收。
- **优化实现（浅水方程）**：高度 + 速度场，半拉格朗日（或 MacCormack）平流，能表达岸边爬升、尾迹、绕流。
- **跟随相机**：模拟网格以相机为中心，移动整格时滚动贴图（环形寻址），避免重采样模糊。
- **注入源**：角色、船、落入水中的物体（来自 PhysicsWorld）。
- **合成**：局部高度/法线叠加到 FFT 海面上；泡沫写入同一张持久泡沫贴图。

### 2.5 海面渲染
| 效果 | 做法 |
|---|---|
| 无限海面与 LOD | 相机中心的几何 clipmap（同心环网格，逐级粗化），顶点采样位移贴图；远处到地平线平滑过渡 |
| 菲涅尔 | Schlick，$F_0 = 0.02$（水的折射率 1.33） |
| 阳光碎闪 | 高频法线 + GGX；远处把未解析的细小斜率转成粗糙度（斜率方差 → 粗糙度），否则远海会闪烁或过于光滑 |
| 天空与云反射 | 环境探针（天空+云渲染进立方体贴图，按粗糙度预滤波），近处叠加屏幕空间反射 |
| 浪尖透光 | 近似次表面散射：观察方向背对太阳、浪高越高越亮，颜色取水体散射色 |
| 折射与水体颜色 | 屏幕空间光线步进折射 + 按 RGB 的 Beer–Lambert 吸收（与 M6 的 Medium 共用参数） |
| 焦散 | 先动画贴图（M6），再 compute 光线步进 + 原子累积（含色散）作为优化实现 |
| 雨滴 | 雨天时叠加程序化涟漪法线 |

### 2.6 与引擎其他部分的连接
- **Medium**：`Medium::Query` 的水面高度/法线来自海洋（CPU 端用低分辨率的 FFT 回读，异步、晚 2–3 帧；或 Gerstner 近似 —— M6 取舍）。
- **浮力**：PhysicsWorld 每个固定步长按 Medium 的水面高度施加浮力。
- **天气**：风速、风向、浪高缩放、泡沫量都由天气系统驱动（见 3.4）。

## 3. 大气与天气系统

目标效果：晴朗 / 多云 / 阴天 / 下雨 / 雷暴；云由噪声生成、可动态生长消散；天气之间自然渐变；日出日落的大气色彩、光束（丁达尔效应）、闪电照亮云层。

### 3.1 物理大气（取代现在的渐变天空）
- **Hillaire 2020**（UE Sky Atmosphere）：瑞利 + 米氏 + 臭氧吸收。
  - 透射 LUT（256×64）、多重散射 LUT（32×32）、天空视图 LUT（192×108，每帧）、空气透视体积（32×32×32 froxel）。
- 接口不变：`SkyRadiance(dir, L, withSun)` 改为查 LUT，材质与海面反射自动受益。
- 太阳透射率随仰角变化 → 太阳光颜色由大气**算出来**（黄昏自然变橙红），不再手调。

### 3.2 体积云
- **形状**：天气图（2D：覆盖率、云类型、降水量）× 云类型高度剖面 × 3D Perlin–Worley 基础噪声（128³）− 3D Worley 细节噪声（32³），再用 curl 噪声扰动边缘。噪声体积离线或启动时用 compute 生成。
- **光照（参考实现）**：沿视线光线步进，每步向太阳方向做少量步进求光学深度；Beer 定律 + Powder 项；双瓣 Henyey–Greenstein 相函数（前向银边 + 后向）；多重散射用多级八度近似（Wrenninge 2013）。
- **光照（进阶实现）**：参考 HPVolumeCloud 的 **phi_fwd 漫射场**：在厚云区域用扩散近似（$-D\nabla^2\phi + \sigma_a\phi = Q$，亥姆霍兹形式，格林函数 $e^{-\kappa r}/4\pi r$），沿太阳方向一维离散累积，加顶部/底部边界置信度与密度门控 —— 让厚云内部与云底不发黑。与参考实现在 ImGui 中切换对比。
- **性能**：1/4 分辨率渲染（每帧只更新 1/16 像素的棋盘格）+ 时间重投影累积 → 依赖 **TAA 与历史缓冲**基础设施。
- **云影**：从太阳方向渲染一张云透射率贴图，作为 `LightingInputs` 的一部分投到海面、地形与角色上。
- **光束（god rays）**：froxel 体积雾中采样云影与阴影，得到穿过云隙的光柱。

### 3.3 降水与闪电
- **雨**：相机周围 GPU 粒子（实例化雨丝），用俯视深度图遮挡（屋檐下不下雨）；屏幕雨滴层；地面溅射；海面涟漪法线。
- **湿润**：雨量累积到「表面湿度」，通过 Medium / 材质共享函数让所有材质变暗、变光滑、出现积水 —— 「材质读取介质」的自然延伸；雨停后逐渐变干。
- **闪电**：按天气的闪电频率随机触发。云内瞬时点光源 + 云体积内自发光（照亮云团，见参考截图） + 天空闪光 + 可选闪电条带网格；对 `LightingInputs` 是一个短暂的强光源（「光即叙事」）。之后接入雷声（按距离延迟）。

### 3.4 天气状态与渐变
天气是一组**参数**，而不是一组开关：

```cpp
struct WeatherState {           // 每个预设一份，存于 config/weather/*.json
    float cloudCoverage;        // 天气图覆盖率阈值
    float cloudType;            // 0 层云 → 0.5 积云 → 1 积雨云（高度剖面）
    float cloudDensity, cloudAbsorption;
    float precipitation;        // 0..1，驱动雨粒子、湿润、海面涟漪
    float lightningRate;        // 次/分钟
    float windSpeed, windDirDeg;// 同时驱动云移动与海洋频谱
    float waveHeightScale, foamAmount;
    float fogDensity, aerosolMie;  // 雾气与大气浑浊度
    float sunIntensityScale;
};
```

- **渐变**：WeatherSystem 持有「当前 → 目标」两个状态，按设定时长用平滑曲线插值所有参数。
  - 云是**长出来/消散**，不是淡入淡出：覆盖率阈值随时间移动，天气图随风平流，云团自然生长。
  - 海洋：风速变化时在两套初始频谱 $\tilde h_0$ 之间插值，避免整片海面「换一张」的跳变。
  - 降水、湿润、雾按各自的时间常数追随（下雨比云来得慢，地面变干比雨停更慢）。
- **预设**：晴朗、少云、多云、阴天、小雨、暴雨、雷暴；编辑器「环境」面板可一键切换、调渐变时长、手动拖动各参数。

### 两种推进顺序
- **按表顺序**：先打基础（资源层、地形物理），海洋与天空在 M5、M6.5 到来。适合「先把引擎骨架搭稳」。
- **海天优先**：M5 海洋 → M6.5 大气与天气 → M3.5 资源层 → M4 地形物理 → M6 介质水下 → M7 → M8。开阔海面与天空几乎不依赖资产和地形，能最快看到截图那样的效果；需要把 TAA、3D 贴图、环境探针这些前置设施提前到 M5 一起做。岸线泡沫和海床等到 M4 地形完成后再接上。
